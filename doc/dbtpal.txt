1. INTRODUCTION                                        *dbtpal-introduction*

dbtpal.nvim runs dbt from Neovim using the `dbt` CLI. It provides a
single pass-through command plus picker workflows for selecting models
and graph neighbours.

There are no mandatory runtime dependencies.

==============================================================================
2. REQUIREMENTS                                        *dbtpal-requirements*

  - Neovim >= 0.12 (`vim.system()` is required)
  - dbt >= 1.0 installed and on `PATH`, or configured explicitly

Optional picker backends:

  - telescope.nvim (only if `picker_backend = "telescope"`)
  - mini.pick (only if `picker_backend = "mini.pick"`)

==============================================================================
3. SETUP                                                    *dbtpal-setup*

>lua
  require("dbtpal").setup({
    path_to_dbt = "dbt",
    path_to_dbt_project = "",
    path_to_dbt_profiles_dir = vim.fn.expand("~/.dbt"),
    include_profiles_dir = true,
    include_project_dir = true,
    include_log_level = true,
    extended_path_search = true,
    protect_compiled_files = true,
    custom_dbt_syntax_enabled = true,
    picker_backend = "default",
    use_current_model = true,
    output_mode = "float",
    pre_cmd_args = {},
    post_cmd_args = {},
  })
<

The following options matter most:

  `picker_backend`  `"default"`, `"telescope"`, or `"mini.pick"`.
  `use_current_model`  When true, `run`, `test`, `compile`, and
                    `build` without `--select` use the current model.
  `output_mode`     `"float"` opens output always; `"notify"` opens
                    output on failure or `:Dbt!`.

`path_to_dbt`, `DBT_EXECUTABLE`, `path_to_dbt_profiles_dir`, and
`DBT_PROFILES_DIR` select the dbt binary, project, and profile. dbt
itself resolves `profiles.yml`, targets, adapters, variables, and
environment overrides.

==============================================================================
4. COMMANDS                                                *dbtpal-commands*

                                                              *:Dbt*
:Dbt {cmd} [args]   Run any dbt command, e.g.: >
  :Dbt run
  :Dbt test --select my_model
  :Dbt compile --select my_model
  :Dbt build --full-refresh
  :Dbt debug
<
With no arguments, `:Dbt` shows usage. Arguments are forwarded to dbt
as a list; dbt resolves selectors, targets, profiles, and variables.

When `use_current_model` is enabled and no `--select` or `-s` is
given, `run`, `test`, `compile`, and `build` use the current SQL/dbt
buffer model. Outside a model buffer the command warns and aborts.
Use `--select '*'` for an explicit whole-project run.

                                                             *:Dbt!*
:Dbt! {cmd} [args]  Same as `:Dbt`, but always opens floating output.

                                            *:DbtSelectModels*
:DbtSelectModels    Pick one or more models, choose `run`, `test`,
                    `compile`, or `build`, then choose `Notify only`
                    or `Open full output`.

The selection is passed as one `--select` value using resource names.
`run` and `build` may modify the database; `test` tests existing
relations; `compile` only renders SQL.

                                          *:DbtSelectUpstream*
:DbtSelectUpstream  Pick from upstream models, seeds, and snapshots,
                   excluding the current model.

                                        *:DbtSelectDownstream*
:DbtSelectDownstream
                    Same as above, for downstream dependents.

                                            *:DbtSelectFamily*
:DbtSelectFamily    Same as above, for upstream and downstream family.

Each graph picker offers `open`, `run`, `test`, `compile`, `build`,
and `refresh`. `open` edits the resource path; `refresh` reruns
`dbt ls`. Execution also offers `Notify only` or `Open full output`.

5. LUA API                                                      *dbtpal-lua*

>lua
  require("dbtpal").setup({ ... })
  require("dbtpal").run_command("run", { "--select", "orders" })
  require("dbtpal").list_resources({ resource_type = "model" }, cb)
  require("dbtpal").select_models()
  require("dbtpal").select_upstream()
  require("dbtpal").select_downstream()
  require("dbtpal").select_family()
<

Arguments are structured lists only, never shell strings: >

  require("dbtpal").run_command("compile", { "--target", "prod" })
<

Lower-level modules remain available for integrations:

  `require("dbtpal").context`    buffer and project context
  `require("dbtpal").selectors`  selector constructors
  `require("dbtpal").execute`    `vim.system()` runner
  `require("dbtpal").picker`     picker registry and backends

==============================================================================
6. PICKERS                                                  *dbtpal-pickers*

Set the backend with: >

  require("dbtpal").setup({ picker_backend = "default" })
<

  `default`     Dependency-free `vim.ui.select()`. Multi-select is
                repeated selection ending with `Done`.
  `telescope`   Optional Telescope adapter, single selection.
  `mini.pick`   Optional mini.pick adapter, single selection.

Multi-selection falls back to the built-in implementation when an
adapter supports only single selection. Cancel with `<Esc>` or `<C-c>`;
cancelling a prompt aborts that workflow.

==============================================================================
7. PRIMITIVES                                            *dbtpal-primitives*

The layers are independent:

  context    Reject non-file, Oil, terminal, help, and non-SQL buffers
             when a model is required. Normalize `oil://` URIs.
  execute    Use the configured executable and `vim.system()`. Pass
             arguments as a list. Add project/profile options once.
             Return stdout, stderr, and exit code. Notify on
             start/completion; surface failures.
  resources  Run `dbt ls --output json` and normalize each row to
             `unique_id`, `name`, `resource_type`,
             `original_file_path`, `path`, and `package_name`.
             Malformed JSON and nonzero exits are errors.
  selectors  `model`, `+model`, `model+`, `+model+`, `tag:name`, and
             `path:dir`. Selectors use resource names, not artifact
             `unique_id` values.
  picker     Core returns resources and accepts selections. Adapters
             implement `select(opts, callback)` and optionally
             `select_many(opts, callback)`.

==============================================================================
8. COMPATIBILITY                                      *dbtpal-compatibility*

The compatibility surface is the CLI: `ls`, `run`, `test`, `compile`,
`build`, and `debug`. The plugin does not import Python dbt or Fusion
internals. Adapter, package, Python-model, flag, artifact, and `dbt ls`
differences surface as command errors.

`dbt compile` renders SQL; it does not guarantee executable output.
Use `run`, `test`, or `build` to execute or validate relations.

==============================================================================
9. DEVELOPMENT                                            *dbtpal-development*

Install hooks once: >

  pre-commit install
<
Run hooks and tests: >

  pre-commit run --all-files
  make test
<
Tests run in headless Neovim with no Plenary dependency. Formatting
uses StyLua; linting uses Selene.
